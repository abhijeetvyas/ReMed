2 · Flow A — Photo intake — verified end-to-end by a simulated-clock test

📷 User sends photo
ack within ~2 s, before any reading
“Got it. Reading your prescription…”
① AI Extract image → {medicines[{name, form, tablets_per_dose, slots, food, days}]}
✅ Validator days 1–90 · ≥1 slot · slots/food/meal times parseable · no instant-burst rule
fail → 1 retry → generic failure copy + “type it in your own words” (empty draft stays open so typed text still works)
🔒 DRAFT SHOWN — nothing scheduled yet fixed line format: NAME — meal slots — before/after food — [# tablets if ≠ 1] — # days
tz line: “Scheduling in IST (UTC+5:30)” + meal defaults (8:00 / 14:00 / 19:00)
buttons: [ ✅ Yes, start my reminders ] [ ✏️ Something's wrong → Flow B on the draft ]
user taps ✅
APPLY — one transactionchangesets.apply_session 1 prescriptions row + N medicines rows
+ whole course expanded into dose_events (15 days × 2 slots = 30 rows) + reminder_queue rows with precomputed send_at (meal anchor ± offset → UTC)
✅ “All set — N doses scheduled over the next X–Y days” today's remaining slots · per-medicine course-end dates · tip line
⚠️ As-built detail: expansion skips times already past — confirming at 3 PM never re-fires the morning's slots. Also: two medicines that share (day, slot, food) share one reminder group, so “✅ Taken — all N” can never ack a different day's dose.

3 · Flow B — Edit Prescription — free text, AI-processed; the flow most covered by tests

“Edit Prescription” / /edit · works while paused · opens on the draft too
Prompt with examples (“actually 5 days and before food”, meal times, offsets, “stop Dolo 650”)
user types anything
② AI Interpret edit IN: free text + current users/prescriptions/medicines JSON · temperature 0 · one call per iteration
change-set JSON (ops · target · fields → update / add / remove medicine · set meal time · set offset · set timezone · cancel prescription)
✅ Validate change-setchangesets.py fuzzy name match · 2+ matches → one clarifying question, no proposal · all-or-nothing (invalid op ⇒ whole edit rolled back)
valid
🔒 FULL updated prescription table [ ✅ Apply ] [ ✏️ Wrong — try again ] — retry loop until Apply · unparseable → generic failure copy, same voice as intake failures
Apply — one transaction
Recompute future rows only meal/offset/timezone → recompute send_at of future pending events (all active prescriptions)
medicine changes → recreate that medicine's future rows · taken/skipped history is immutable — an explicitly answered dose is never re-reminded, even if its slot moves
🧪 Regression story: the tests caught two would-be-nasty bugs — future-day doses ackable via one button, and meal-time edits resurrecting taken doses. Both fixed and locked by tests.

4 · Flow C — Reminder tick — verified with simulated clock incl. outage drill

Tick (every 30 s, injected “now” in tests) ① missed sweep (window passed → silent missed; orphaned sending rows released)
② query due: send_at ≤ now · state=pending · dose pending · user not paused · LIMIT 200
group by reminder_group → mark in-flight (no double-send)
One message per slot group “⏰ 7:45 AM — 15 min before breakfast” + medicine lines + buttons
single: [ ✅ Taken ] [ ⏭ Skip today ] · grouped: [ ✅ Taken — all N ] [ ⏭ Skip today ]
Bot API ok = delivered → state=sent, message_id stored
Send fails? ≤3 attempts w/ backoff inside window → then expired, silently. No nag.
✅ tested: 3 attempts, then silence
User taps ✅ / ⏭ status ← taken / skipped · responded_at stamped · buttons clear, NO reply message · replayed press ignored
✅ tested: silent ack + idempotency
Window passes unanswered / paused → missed, recorded silently · raw rows only, no summaries (the future doctor-product fuel)
✅ tested: pause blocks send, window still expires

5 · Data model — 6 tables · SQLite · all times UTC + user IANA tz

TableKey fields as implemented
userschat_id 🔑 · timezone · meal_breakfast/lunch/dinner · offset_before_min (−15) · offset_after_min (45) · paused · created_at · deleted_at
prescriptionsid 🔑 · chat_id · start_date · end_date (computed) · status: active | cancelled | expired · image_deleted (=1; we never persist photos)
medicinesid 🔑 · prescription_id · name · form · tablets_per_dose (≠1 only shown) · slots (json) · food · duration_days · removed**
dose_eventsid 🔑 · medicine_id · chat_id · event_date · slot · scheduled_time_utc · status: pending→taken|skipped|missed · responded_at · reminder_message_id · reminder_group**
reminder_queuedose_event_id 🔑 · chat_id · send_at · state: pending|sending**|sent|failed|expired · attempts · last_error
conversation_statechat_id 🔑 · state: pending_draft | pending_edit | pending_delete · payload (unapplied session JSON) · expires_at (30 min TTL)

\*\* = added during build (not in the deep-dive field list): removed soft-deletes medicines while keeping adherence history joinable; reminder_group scopes button acks to one message (day+slot+food); sending is the in-flight state that prevents double-sends across ticks/crashes.
Indexes per deep dive §7: queue(send_at,state) · events(chat_id,event_date) · medicines(prescription_id).

State machines (small, enumerable)

EntityPath
Prescriptiondraft → active → cancelled | expired (computed)
Dose eventpending → taken | skipped | missed (silent)
Reminder jobpending → sending → sent | (fail → retry ≤3 → expired, silent)
Conversationnone ↔ pending_draft | pending_edit | pending_delete (TTL 30 min)

Privacy mechanics

• photos never written to disk — bytes live only inside the AI call
• chat_id = the only PII
• /delete: one transaction, all six tables, typed “YES” gate
• logs: no message contents, no medicine names — chat_id allowed for support
